# Paradise Camp Fire replay: data, grid and status

This document records the real-data chain behind the Paradise replay. It is deliberately stricter than the synthetic exercise: every layer is labelled **observed**, **derived**, **predicted**, **scenario**, **assumed**, **missing** or **synthetic**, and a missing layer is never filled with invented values.

## 1. Frozen inputs

| Layer | File | Source | Status |
| --- | --- | --- | --- |
| FIRMS detections | `data/paradise/camp_fire_firms_2018.json` | NASA LANCE FIRMS, VIIRS S-NPP and NOAA-20 standard processing, 2018-11-08/09 query | observed points |
| NIST timeline | `data/paradise/camp_fire_nist_timeline.json` | NIST TN 2135 maps 2–5 | verified time windows only; spatial symbols not digitized |
| NIST file verification | `data/paradise/nist_source_verification.json` | nist.gov PDF endpoints | hashes, byte sizes and page counts verified |
| Population | `data/paradise/population_acs_2017_block_groups.geojson` | 2017 TIGER block groups + 2013–2017 ACS 5-year | derived area-level exposure |
| Geography | `data/paradise/geography_2025.geojson` | 2025 TIGER place + Butte County roads | observed geometry, wrong vintage for 2018 operations |
| Terrain samples | `data/paradise/terrain_3dep_7x7.json` | USGS 3DEP point query, 2022 acquisition | derived-coarse display mesh |
| Shared grid | `data/paradise/paradise_grid_500m.json` | build of the layers above | derived, frozen |
| Quality report | `data/paradise/data_quality_report.json` | build of the layers above | machine-readable checks |

The FIRMS package contains **2,017 detections in 9 acquisition snapshots**, from 2018-11-08 11:50 PT to 2018-11-09 14:01 PT. The first five hours of the fire (NIST windows 06:25–10:00 PT) have no FIRMS detections in this package. The largest observation gap is **688 minutes** (21:30 UTC to 08:58 UTC). Both facts are surfaced in the UI and in the metrics evidence status.

## 2. Shared 500 m grid

- Resolution: **500 m**.
- Extent: 2018/2025 Paradise town boundary buffered by **3,000 m**.
- Cells: **841** in a **29 × 29** layout.
- CRS: `LOCAL:PARADISE_EQUIRECTANGULAR_M`, a documented local metric grid. It is **not** EPSG:32610 and not an official survey datum.
- Formula:
  - `x_m = (lon - origin.longitude) * meters_per_degree_longitude`
  - `y_m = (lat - origin.latitude) * meters_per_degree_latitude`
  - origin `(-121.70, 39.68)`, `meters_per_degree_latitude = 110574`, `meters_per_degree_longitude = 85595`.
- Cell ID rule: `P-{row:02d}-{col:02d}`, row 0 at the southern edge, col 0 at the western edge. IDs are stable across 2D, 3D, the backend model and the API.
- Each cell records its centroid, WGS84 bounds, elevation, slope, population, population MOE, road length, road names, fuel default, source/method strings and explicit status flags.

Population mapping: the town-clipped 2017 ACS block groups are area-weighted into cells. The total is 21,785 people, which is 17.6% below the ACS place estimate of 26,437; this gap is a declared limitation. The layer has no addresses or resident locations. Synthetic residents are generated later from these cell totals and are clearly labelled simulated.

Road mapping: 2025 TIGER/Line road segments are intersected with each cell. The layer has no closures, lane capacity, traffic speed or evacuation permissions.

Terrain: the 7 × 7 USGS 3DEP samples are interpolated to cell centroids and differentiated for slope. The sample spacing is about 1.2 km and the acquisition date is 2022, after the fire. Cell slope is `derived-coarse` and is not a modeling DEM.

Fuel: every cell uses a declared default of 0.7 because no LANDFIRE layer is bundled. Water and critical facilities are marked **missing**.

## 3. Data quality gates

`data/paradise/data_quality_report.json` is generated by:

```bash
.venv/bin/python scripts/build_paradise_data_quality.py
```

It currently reports 11 pass, 8 warn, 4 blocked and 3 context checks. The blocked items are:

1. NIST spatial symbols are not digitized.
2. No observed fuel layer.
3. No water/hydrant/draft-site layer.
4. No critical-facility layer.

Warnings include the FIRMS morning gap, the 2025 road vintage, the 2013–2017 ACS vintage, the 17.6% population reconciliation gap, the 7 × 7 terrain mesh and its post-fire 2022 acquisition. The report is served at `/api/v1/paradise/data-quality` and rendered in the site's data-status panel.

NIST PDFs were re-downloaded and their SHA-256 hashes match the manifest. Their symbols and annotations are embedded in a 14,370 × 9,746 raster; no machine-readable spatial layer was extracted. NIST therefore remains a **temporal constraint** only and cannot be used for spatial scoring.

## 4. Rebuild

Local build dependencies are not part of the runtime image:

```bash
.venv/bin/pip install -r scripts/requirements-build.txt
.venv/bin/python scripts/build_paradise_grid.py
.venv/bin/python scripts/build_paradise_data_quality.py
# optional, downloads ~105 MB from nist.gov:
.venv/bin/python scripts/verify_nist_sources.py
```

The FIRMS and population packages are built once with the user's own keys, as documented in `data/paradise/SOURCES.md`. Keys are read only from environment variables and are never written to the repository, logs or images.

## 6. Remaining limits

- FIRMS points are active-fire detections, not a perimeter or burn scar.
- NIST spatial symbols are not digitized.
- The morning ignition phase has no mapped observations.
- Fuel, water, facilities and official shelters are unavailable.
- Population and roads are not 2018 operational records.
- The 3D view is a viewing aid, not a fire-behaviour model.
- This is a research prototype and cannot issue warnings, evacuation orders or dispatches.

## 7. Historical replay

`GET /api/v1/paradise/replay` returns a frozen replay package with:

- 14 frames: 9 FIRMS observation frames and 5 NIST window boundaries;
- 2,017 detections aggregated into 591 observed cells;
- 328 detections outside the shared grid, counted but not mapped;
- the 688-minute overnight gap preserved as a gap, with no inserted fake frames;
- observed time in UTC and America/Los_Angeles;
- per-frame source, data-status, observation count, cumulative detected cells, outside-grid count and observation-latency status.

NIST-only frames carry zero hotspot cells and `spatial_status: "not_digitized"`. The replay does not interpolate a perimeter. The cumulative cell layer is explicitly described as a **detection proxy, not a burn scar**. Weather is `missing` in the replay package because no historical station record is bundled.

The replay ID is a hash of the event, data version and the real frame times, so the same frozen inputs always produce the same replay.

## 8. Time-forward evaluation

`GET /api/v1/paradise/evaluation` serves the precomputed
`data/paradise/camp_fire_evaluation.json`. The protocol is strict:

1. issue at FIRMS snapshot `t0` using only detections with `acquired_at <= t0`;
2. score against cells first detected in `(t0, t1]` at the next snapshot;
3. never use `t1` detections as a forecast input;
4. report sample counts, lead time and an evidence status per lead bucket.

| Lead bucket | Windows | Observed new cells | Matched | Evidence | Precision | Recall | IoU |
| --- | ---: | ---: | ---: | --- | ---: | ---: | ---: |
| 45–60 min | 6 | 306 | 217 | sufficient | 0.254 | 0.709 | 0.230 |
| 75–180 min | 0 | 0 | 0 | insufficient | — | — | — |
| over 180 min | 2 | 103 | 102 | insufficient (needs 3 windows) | 0.149 | 0.990 | 0.149 |

Short-lead comparison with the isotropic 1.5 km/h radial baseline:

| Variant | Precision | Recall | IoU | Arrival median abs error |
| --- | ---: | ---: | ---: | ---: |
| Current wind/slope model | 0.254 | 0.709 | 0.230 | 21 min (217 cells) |
| Radial baseline | 0.195 | 0.967 | 0.194 | not modelled |
| Persistence baseline | — | 0.000 | 0.000 | not modelled |

The current model has higher precision and IoU than the radial baseline but **lower recall**: the radial baseline over-predicts over a wide area and catches more detections. This is reported as a trade-off, not as a win. The long-lead bucket is over-predicted and is marked **evidence insufficient** because only two windows exist.

Population metrics use the ACS cell totals. For the short bucket the observed exposed population is 11,721 and the predicted exposed population is 16,136 (absolute error 4,415; median per-window relative error 0.131). Nearest miss distance is 604 m; nearest false-alarm distance is 1,266 m.

NIST is not used for spatial scoring. Its symbols are not digitized, and the evaluation package says so. The metrics answer **detection agreement**, not life-safety performance.

## 9. Forecast API

`GET /api/v1/paradise/forecast?at=<ISO8601>&lead_minutes=60` returns a deterministic ensemble forecast. It refuses to forecast before the first observation (`status: "no_observations"`), uses only past seeds, and includes:

- ensemble probability per cell, median arrival time and seed/new flags;
- predicted new cells and predicted exposed population at the 0.5 threshold;
- the declared weather assumption (`scenario-assumption`);
- the default fuel value, missing water and coarse terrain assumptions;
- model version, data version, parameter set and limitations.

Scenario query parameters `wind_speed_multiplier`, `wind_direction_delta_deg` and `suppression_effectiveness` change a copy of the forecast; they never change the frozen baseline or the active model.

## 10. Linked 2D / 3D replay console

The site now opens with the real Paradise replay above the legacy synthetic exercise. The 2D and 3D views share:

- the same 841-cell grid and `P-row-col` IDs;
- the same selected replay frame and real UTC/PT time;
- the same forecast object, lead time and scenario;
- the same observed-cell set, hotspot set and predicted probabilities;
- the same population exposure and source labels.

2D view: real TIGER roads, town boundary, observed FIRMS cells, new hotspots sized by FRP, predicted risk cells, population bars and a cell inspector.

3D view: instanced terrain tiles derived from the 7×7 3DEP mesh, flat orange observed tiles and thin predicted-risk columns. It is a viewing aid, not a fire-height or fire-behaviour model. If WebGL is unavailable, the component calls the fallback and the console returns to the 2D map automatically.

Timeline: 14 real frames, play/pause, 0.5×/1×/2×/4× speed, scrubber, previous/next FIRMS observation, frame strip and explicit gap labels. NIST-only frames show a badge saying their spatial symbols are not digitized and no forecast is fabricated.

The legacy 3×3 synthetic exercise remains available inside a collapsed **Synthetic 3×3 exercise (legacy)** section. It is not presented as a historical result.

The URL parameter `?view=scene` or `?view=split` can open the 3D or split view directly for a demo; `?view=map` is the default.
